# 变体B 实验结果：Tokenizer 重训练

> **测试日期**: 2026-05-07  
> **方法**: 用相同基础语料训练 baseline BPE，用加入部首/声旁注释的增强语料训练 enhanced BPE  
> **评测指标**: 各类汉字的 token 数（越少越好，1 token = 整字被识别为独立单元）

---

## 实验设计

| | Baseline | Enhanced |
|---|---|---|
| 语料 | 标准中文句子（约1200行） | 同上 + 部首注释、声旁族群、形声字分析（约2700行） |
| 词表大小 | 3000 | 3000 |
| 算法 | BPE（ByteLevel） | BPE（ByteLevel） |

---

---

## 核心发现

### F-B1：部首注释语料显著提升生僻字的 tokenization 效率

7/8 个生僻形声字（汸/棻/炇/砯/犴/浯/朸）从 2 tokens → 1 token。  
原因：增强语料中这些字频繁出现，BPE 学到了将整字合并为单一 token 的规则。

### F-B2：常见字也有改善，无负面影响

清（3→1）、江（2→1）、湖（2→1）均有改善，且所有已经是 1 token 的字保持不变。  
**这说明增强语料对常见字无害，只有益处。**

### F-B3：汭（汭）持平——原因是语料中出现频率仍不足

汭在增强语料中出现次数较少，BPE 未能学到足够的合并规则。  
→ 解决方案：增加汭相关的语料行数（简单可做）。

### F-B4：叠加构字（淼/犇/鱻）未改善——字符 bytes 模式太独特

这类极生僻字（Unicode 扩展区）的 UTF-8 字节序列独特，即使增加出现频率，BPE 也需要更大词表才能合并。  
→ 解决方案：增大 vocab_size（从3000到5000+）或直接在语料中大量重复这些字。

---

## 与变体A的联系

变体A 发现：**给生僻字在 prompt 里加部首/声旁注释，能帮助模型推理**。  
变体B 发现：**在训练语料里加部首/声旁注释，能帮助 tokenizer 把生僻字识别为整字**。

两个发现相互印证：部首/声旁信息在 **推理阶段（变体A）** 和 **训练阶段（变体B）** 都有价值。

---

## 局限性

1. **语料规模小**：本实验语料约2700行，真实应用需要百万级别语料
2. **词表小**：3000词表远小于实际模型（GPT-4 约10万），结果仅为概念验证
3. **未测试下游任务**：只测 tokenization 效率，未测对 NLP 任务的影响
4. **ByteLevel BPE**：实际大模型用的是更复杂的 SentencePiece 或 tiktoken，行为可能不同

---

## 结论

> **部首/声旁注释语料能显著提升 BPE tokenizer 对生僻字的切分效率（7/8字从2→1 token），且对常见字无负面影响。这为「字典信息辅助 tokenizer 训练」提供了概念验证。**
