## 三大核心发现

### 发现1：词表扩大本身就能改善生僻字 tokenization

7/8 个原始测试生僻字（汸/棻/炇/砯/犴/浯/朸）在**大规模 baseline（无增强）**下就已经是 1 token——词表从 3000 扩到 30000，BPE 有了足够的合并规则空间，即使没有部首注释语料也能学到整字 token。

**含义**：生僻字 tokenization 差的根本原因是**词表不够大**，部首注释只是提升合并频率的辅助手段。

### 发现2：增强语料在大规模下仍然有额外价值

大规模 baseline 已经很强的情况下，enhanced 进一步改善了 4 个字：

| 字 | baseline(30K) | enhanced(30K) |
|----|:---:|:---:|
| 洭 | 2 | **1** |
| 泶 | 2 | **1** |
| 湸 | 2 | **1** |
| 泫 | 2 | **1** |
| 清 | 2 | **1** |
| 江 | 2 | **1** |
| 湖 | 2 | **1** |
| 犭 | 2 | **1** |

这些都是大规模语料中出现频率仍然不足的字——增强语料通过重复这些字，补齐了频率缺口。

**含义**：部首注释语料的价值在大规模场景下仍然存在，但从"必要条件"降级为"锦上添花"。

### 发现3：叠加构字（淼/犇）无论如何都难以改善

淼（三水）和犇（三牛）在所有条件下都是 2 token——它们的 UTF-8 字节序列过于独特，即使出现频率高，BPE 的合并规则仍然无法学到完整字。

**含义**：这类字需要语言学感知的分词方法（如基于字形的 tokenizer），纯统计 BPE 的天花板就在这里。

## 跨规模对比：增强语料价值随词表增大而变化

```
词表 3000（小规模）：
  增强语料价值 = 高（7/8 生僻字从2→1，是关键因素）

词表 30000（大规模）：
  增强语料价值 = 中等（4/8 额外生僻字从2→1，是补充因素）

预期词表 100000（真实模型规模）：
  增强语料价值 = 低（大多数字在大词表+大语料下自然合并）
  但对超极生僻字（Unicode 扩展区）仍有价值
```

## 对汇报的建议表述

> "我们分两个规模验证了部首注释语料对 BPE tokenizer 的影响：小规模实验（词表3000）中，增强语料使7/8生僻字从2 token改善为1 token，效果显著；大规模实验（词表30000，百万行语料）中，词表扩大本身就解决了大部分问题，增强语料进一步改善了4个词表大但语料频率不足的字。叠加构字（淼/犇）在两种规模下均无法改善，需要超出纯统计BPE能力范围的方法。"

## 局限性

1. **语料来源**：本实验语料由重复句子构成，分布不如真实网络语料多样
2. **未测下游任务**：只测 tokenization 效率，未验证对 NLP 任务准确率的影响
3. **词表上限**：GPT-4 词表约 100K，tiktoken 使用不同算法，真实结论需在更大规模验证
